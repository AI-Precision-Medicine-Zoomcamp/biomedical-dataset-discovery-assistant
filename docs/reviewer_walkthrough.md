# Reviewer Walkthrough

This walkthrough is the shortest path for reviewing the Biomedical Dataset
Discovery Assistant as an LLM Zoomcamp capstone.

## 1. What The Project Does

The assistant helps research users find candidate public biomedical datasets
from normalized GDC and cBioPortal metadata. It is a dataset discovery tool, not
a clinical or biological interpretation system.

The core user question is:

```text
What public datasets can support KRAS G12C research in NSCLC?
```

The important behavior is not only returning `TCGA-LUAD` or `TCGA-LUSC`. The
assistant should also say when KRAS G12C-positive case counts are not explicitly
verified by the current metadata.

## 2. Fast Local Review

Install and test:

```bash
uv sync
make test
make pipeline
```

Or run the full no-API-key local reviewer check:

```bash
make reviewer-check
```

This writes:

```text
docs/evaluation_report_seed.md
```

Run the Streamlit reviewer UI:

```bash
make ui
```

Open:

```text
http://127.0.0.1:8501/
```

Try this question:

```text
Are there public datasets for KRAS G12C NSCLC with RNA-seq data?
```

Expected reviewer observations:

- the answer names candidate datasets
- retrieved datasets are visible beside the answer
- source links are visible when available
- the tool trace shows catalog search and grounded-answer steps
- uncertainty is explicit when variant-positive cases are not verified

The default `Local reviewer mode` does not require an API key. It runs the
transparent deterministic tool workflow and exposes the same retrieved records
and tool trace used by the answer. Reviewers with `OPENAI_API_KEY` can select
`Live OpenAI RAG` to call the OpenAI Responses API.

## 3. Feedback And Monitoring

Submit a rating from the UI, or use:

```bash
curl -s -X POST http://127.0.0.1:8000/feedback \
  -H "Content-Type: application/json" \
  -d '{"question": "Which datasets exist for NSCLC?", "rating": 5, "comment": "Useful answer."}'
```

Open:

```text
http://127.0.0.1:8501/
```

Select the **Monitoring** tab.

Expected reviewer observations:

- total feedback count is visible
- average rating is visible
- rating distribution is visible
- recent feedback is visible

Feedback is written to:

```text
data/feedback/feedback.jsonl
```

## 4. Docker Review

Build and run the UI with Docker Compose:

```bash
docker compose up --build
```

Open:

```text
http://127.0.0.1:8501/
```

Stop the app with `Ctrl-C`.

The local compose path has been smoke-tested with:

```text
GET /health -> 200
API and reviewer-ui container status -> healthy
```

## 5. Optional Screencast

Streamlit provides a built-in recording option. Open the upper-right app menu,
select **Record a screencast**, optionally enable microphone audio, and record
the Assistant and Monitoring tabs. A video is helpful for review but is not
required to run or score the project.

## 6. Evaluation Review

Run retrieval comparison:

```bash
make retrieval-compare CATALOG=data/processed/catalog_broad_live.json QUESTIONS=eval/questions_reliability.json
```

Run answer guardrail evaluation:

```bash
make answer-eval CATALOG=data/processed/catalog_broad_live.json QUESTIONS=eval/questions_reliability.json
```

Run reverse claim verification:

```bash
make claim-eval CATALOG=data/processed/catalog_broad_live.json QUESTIONS=eval/questions_reliability.json
```

Generate the transparent report:

```bash
make eval-report CATALOG=data/processed/catalog_broad_live.json QUESTIONS=eval/questions_reliability.json
```

Then read:

```text
docs/evaluation_report_reliability.md
```

For the fully local seed-catalog report generated by `make reviewer-check`,
read:

```text
docs/evaluation_report_seed.md
```

## 7. What Is Still Limited

The project is intentionally honest about these limits:

- GDC broad metadata is project-level, not patient-level.
- KRAS G12C-positive case counts are not verified in the current catalog.
- The local agent has a real tool trace, but the tool order is fixed.
- The monitoring page is a lightweight feedback summary, not production observability.
- GEO, SRA, and deeper cBioPortal clinical/sample metadata are deferred.

These limits are part of the product design: the assistant should help discover
candidate datasets without pretending that shallow metadata proves specific
biological cohort facts.
